# Final demo guide (4–6 minutes)

## Prepare

- Start the backend and frontend using the commands in README. Keep credentials and private tabs out of view.
- Open the saved HTTP and Java lessons and confirm the versions and reviews shown in the workspace. Have `artifacts/openai-acceptance/` available as historical backup; these files do not represent the latest edits.
- Check audio, screen sharing, export downloads and local provider availability. Do not show `.env`.

## Walkthrough

1. **0:00–0:30 — Introduction and dashboard.** Show the library and recent activity. Say: “LessonForge helps an instructor research, create and review a lesson; the instructor makes the final decision.”
2. **0:30–1:00 — Create.** Click **Create a lesson**, show the title and objective inputs and validation. Start a new lesson only if the provider is available and the recording budget permits; otherwise explain the saved-lesson fallback.
3. **1:00–1:45 — Research and lesson.** Open the saved HTTP lesson; click **Sources**. Show a website, book and video. Explain that metadata is discovery information, not a verified reading of a book or video. Return to **Lesson** and show the 42-minute budget and examples.
4. **1:45–2:45 — Independent reviews.** Open **Factual QC**, show severity, evidence and limitations. Open **Teaching QC**, explain the independent instructional rubric. Show a recommendation and preview if one offers a replacement; do not imply that a missing proposal was applied.
5. **2:45–3:45 — Edit and history.** Open a section editor on a disposable demo lesson, make a small change, save and refresh. Show stale review indicators and **History**; explain that restore creates a new version. Avoid altering the reviewed acceptance lessons merely for the recording.
6. **3:45–4:30 — Export.** Open **Export**, download PDF and Markdown, then mention JSON and ZIP. Show the downloaded files and explain that the instructor must review them.
7. **4:30–5:15 — Second lesson and close.** Open Java; show the inheritance, overriding and overloading examples, 43-minute estimate and reviews. Explain the Java examples were compiled separately, and that instructor sign-off remains pending.

## If an API call fails

Show the saved lessons and existing reports, identify them as saved results and state the failure. Use the historical exports as a fallback with their original version label. Do not imply a live generation succeeded if it did not.

Recording and upload are the submitter's responsibility.
